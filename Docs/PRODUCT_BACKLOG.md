# Pocket Ledger — 产品复盘与待办

记录日期：2026-10-14。今天暂停功能修改；此文件仅记录后续方向，不代表功能已实现。此待办随项目源码维护。

## 产品目标

先做到比现有 Shortcuts + Numbers 更顺手、更完整的日常记账，再做有实际价值的 AI 分析。金额、日期、汇总与比较由确定性代码计算，AI 负责理解自然语言、解释有证据的变化和提出可执行建议。

## P0 — 记账闭环与数据可靠性

- **丰富交易模型**：增加独立商家字段、简短标题、详细备注、分类/子分类；保留原始输入供回看。地点、账户、支付方式以后按需求增加，避免强迫每笔填写。先对照用户现有 Shortcut 的实际字段和常用输入建立功能清单。
- **录入体验**：减少点击；自然语言解析后可快速修正商家、金额、日期、类别。处理键盘、焦点、加载反馈、失败重试和防止重复提交。Review Entry 收键盘与 Done 按钮已有初步修复，仍需真实手机验收。
- **日期与币种准确性**：明确当前快速输入日期支持范围，扩展常见日期表达时提供确认，不能把未识别日期默默当作今天。币种明确显示，未实现换汇前不混算多币种。
- **Activity 列表/详情分离**：列表展示简短、有意义的标题、商家、金额与日期；点击进入只读详情，再选择编辑。详情包含备注、分类、原始输入等。不要一点击就直接进入编辑表单。
- **删除体验**：调研以撤销替代每次弹出确认；避免误删并保留恢复路径。验证滑动、列表更新、汇总更新和动画是否协调。
- **可靠保存与可恢复性**：个人账本持久化；解析失败不丢原始输入；保存失败保留草稿；模型新增字段时兼容旧 JSON。增加导出/备份后再作为长期主账本使用。

验收：用真实常见记账情境连续完成录入、修正、查看、编辑、删除/撤销及重启恢复；字段覆盖现有 Shortcut 的主要用法，点击次数和等待时间可比较。

## P1 — 有意义的月度报告

- **现状澄清**：已有当月/上月总支出柱状图、差额和月中同期比较的基础计算，但缺少分类、商家等维度的变化解释。不能把“已有两根柱子”当作完整对比分析。
- **比较事实表**：总收入/支出/净流入、绝对差与百分比、分类变化贡献、商家变化、笔数和单笔均值。上期为零时不显示误导性增长率；区分月中同期和完整月份。
- **AI 洞察**：解释变化主要来自哪些已记录交易，区分频次增加和客单价变化；提示可能的一次性大额支出，并给出可核查、可执行的建议。不能只重复“钱花在哪里”。
- **限制推断**：没有完整数据时不把少记账当成省钱；不能凭交易记录断定用户动机或必需/非必需消费。重复消费或异常检测须注明为推测，允许用户确认。
- **有证据的报告**：每条结论能追溯到分类、商家或具体交易；无足够跨月数据时说明不足。预算建议依据用户设置，不凭空规定合理支出。
- **AI 失败可用**：模型不可用、超时或拒绝时，确定性的比较报告仍完整；AI 文本不能篡改金额与统计结果。

验收：用完整两月、月中、上月为零、缺少记录、一次性大额等数据检查；报告应回答“变了多少、什么导致变化、哪些需要关注”，并能打开相关交易核查。

## P1 — 图表和分类

- 分类支持主类/子类、手动更正与偏好记忆；不要一开始增加过多细分类而拖慢录入。
- 优先考虑：每日支出趋势、分类支出构成、分类环比增减。每张图应回答明确问题，而不是单纯增加图表数量。
- 图表支持月份切换、金额/比例、选中查看及进入交易列表；考虑空数据、暗色模式、可访问性和小屏幕。

## P2 — 性能与视觉

- **性能待测**：用户感觉运行表现需优化，目前尚未定位瓶颈。先测真机启动、滚动、保存/删除、图表刷新和 AI 首次/后续响应，区分 Debug 调试开销与 Release 表现。
- 若测量证明有问题，再考虑减少重复汇总计算、合并刷新、异步工作和缓存；不凭感觉预先重构。
- **图标**：已有青绿色玻璃账本概念，未加入 Xcode；继续简化，验证小尺寸辨识度与主屏幕效果，避免细节过密和泛用 AI 星光抢占主体。

## 建议执行顺序

1. 核对 Shortcut 功能清单，完善交易字段、旧数据迁移与录入流程。
2. Activity 详情、编辑与删除/撤销，完成日常记账闭环。
3. 确定性跨月分析与必要图表。
4. 基于事实表生成有依据的 AI 洞察。
5. 按测量优化性能，再打磨图标与视觉。

后续逐项实施并验收，不以功能数量作为完成标准。
